# U25 — Founder consent cleanup choices

21 November 2026. Founder answered both questions about the independently reviewed [decision memo](../development/evidence/consent-cleanup-founder-choice.md):

> Use the narrow loss-of-consent scope (recommended)

> Remove originals and derived files (recommended)

The selected cohort follows the memo: a qualifying tutoring withdrawal that leaves no qualifying tutoring consent selects older uploads for that learner/purpose across courses/editions. If another guardian still provides qualifying consent, select only the withdrawing guardian's older uploads when that guardian loses their own last qualifying consent. Duplicate, ineffective/expired and unrelated-purpose withdrawals schedule no tutoring cleanup. Preserve unrelated learners/tenants/purposes and all newer objects after the captured pre-withdrawal generation cutoff. A new grant does not revive old objects.

Selected targets lose both the private original and derived manifest, with charges released only after verified deletion. The derived-only retention option and blanket cleanup on every qualifying withdrawal were not selected. No retained-original purpose is approved.

These are product policy choices for the existing synthetic F3 implementation scope. They do not approve real-data use, a new retention timetable or minimum audit-field policy, native execution, provider calls, deployment, gate changes, security exceptions or supplier recovery. Operational metadata and full runtime/transaction/deletion evidence remain subject to the documented G3/privacy and phase requirements. The first implementation slice records intent only; it must not claim files were purged.
