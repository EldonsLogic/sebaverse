## Proposed isolated CI smoke run

1. After independent review of the exact image, definition bundle and run configuration, invoke `clamscan` directly with the explicit read-only signature path. Bypass the image entrypoint, disable image health checks and use no updater or daemon. Give the container a non-root UID, a read-only root, a size-limited `noexec,nosuid,nodev` scratch mount, no network or published ports, dropped capabilities, `no-new-privileges`, and the default seccomp profile. Mount only the positive or negative fixture and definitions read-only. Pass no database, cloud or repository credentials and mount no workspace or host socket. Verify these controls from runtime inspection and a denied network probe.
2. A proposed initial envelope for the smoke run is one scan at a time, 1 vCPU, 4 GiB memory, no swap, 64 processes, 128 MiB scratch and a 60-second outer deadline including signature load. Kill and remove the container on timeout. Set engine input and expanded-byte limits together with file count, nesting and scan-time limits. Verify that the fixture was actually scanned and treat skipped, partial, encrypted and limit-exceeded scans as quarantine outcomes even if the scanner exits successfully. ClamAV documents that its maximum-file-size check can skip a file and assume it clean. [ClamAV scan limits](https://docs.clamav.net/manual/Usage/Scanning.html).
3. Scan the harmless official EICAR test file directly and assert the expected vendor signature and blocked verdict. Exercise the broker separately with an authored allowed-type fixture, such as a small PDF, that receives a clean scan, and a pinned test-only hash rule matching a second authored PDF to prove a detection never invokes the parser. Bind any clean handoff to the exact object hash, manifest, image and bundle. Check missing or corrupt definitions, unavailable scanner, stale or mismatched results, a scan-limit breach, timeout and resource kill. Each negative must leave the upload quarantined with zero parser invocations. Generate fixtures inside disposable CI, retain hashes and bounded results, and use no real malware or personal data. The test-only rule verifies the broker path and stays outside the official bundle. [EICAR fixture](https://www.eicar.org/download-anti-malware-testfile/), [ClamAV hash-rule format](https://docs.clamav.net/manual/Signatures/HashSignatures.html).

Cisco recommends 3 GiB minimum and 4 GiB preferred for use with standard definitions. That is vendor guidance and informs the proposed CI allowance. Capture cold-start wall time, scan latency, peak memory, CPU seconds, timeout/OOM counts, and image/definition/scratch bytes on the exact CI runner. Representative upload throughput, sustained resource cost and any commercial margin remain unmeasured. [Cisco memory guidance](https://docs.clamav.net/manual/Installing/Docker.html#memory-ram-requirements).
