I selected Cisco Talos's Alpine `clamav/clamav:1.5.4_base` because its different distribution could replace the vulnerable Debian `libxml2` lineage and the `_base` variant keeps definition acquisition separate. Docker Hub reported index `sha256:187c76a552c21b8924e08370655c4007eb642baaace9748c5eb46a32672d8d8e`; the `linux/amd64` manifest is `docker.io/clamav/clamav@sha256:fe043f7049c7931b8cb05a9738e2b7d1eb8045ae495ffee9f3bc43d88baadd83`. Registry bytes and both publisher attestation subjects matched their recorded digests. The publisher SPDX lists Alpine 3.24.4 and `libxml2` `2.13.9-r2`; this version is past the upstream 2.11.0 fix for CVE-2026-6653. [Docker Hub metadata](https://hub.docker.com/v2/repositories/clamav/clamav/tags/1.5.4_base), [Cisco Alpine image guidance](https://github.com/Cisco-Talos/clamav-docker/blob/main/clamav/README-alpine.md), [original finding and upstream fix history](https://security-tracker.debian.org/tracker/CVE-2026-6653).

**OpenSSL holds this candidate.** The publisher SPDX lists Alpine `libcrypto3` and `libssl3` at `3.5.9-r0`. They have the same exact package identities, including source package, distro and architecture, as eight High matches in the same-day Grype 0.121.3 report for the prior synthetic PostgreSQL image. Four advisories matched both packages: CVE-2026-95692, CVE-2026-88823, CVE-2026-95691 and CVE-2026-107496. The OpenSSL project rates these Low and lists 3.5.10 as the upstream fix. Alpine's v3.24 main security data returned no matching fix entries for these four IDs. The overlap also includes five Medium matches; none of the joined IDs or aliases appears in the 17 November CISA catalog. These results are limited to the exact package identities shared with the prior report. AUTH-007 applies only to the reviewed PostgreSQL workload.
