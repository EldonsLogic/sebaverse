## One conditional assembly method

Use Alpine's native package database writer as an isolated build tool, after exact tool qualification and only for the expressly approved package set. Alpine publishes `apk-tools-static` `3.0.9-r0` for v3.24/main/x86_64 at aports commit `13685e8f2cf1c103cbba2fb9efcfcf19f4918df0`. Its index lists GPL-2.0-only and zero runtime package dependencies. The Alpine recipe builds an ELF statically and uses OpenSSL and zlib static-library inputs. The distributor's browser lists a separate SHA-256 RSA signature for the executable. The outer archive, detached binary signature, exact embedded-library versions/advisories, source/notice obligations and immutable executable digest need their own review. The 4 November build predates the current OpenSSL fix evidence. The listing and recipe leave its embedded OpenSSL revision unresolved. Treat the tool as a separate build-time dependency; no tool files, packages or notices generated solely for its distribution belong in the PostgreSQL runtime layer. [Exact Alpine package record](https://pkgs.alpinelinux.org/package/v3.24/main/x86_64/apk-tools-static), [Alpine package contents](https://pkgs.alpinelinux.org/contents?arch=x86_64&branch=v3.24&name=apk-tools-static&repo=main), [Alpine v3.24 packaging recipe](https://github.com/alpinelinux/aports/blob/3.24-stable/main/apk-tools/APKBUILD).

1. On a disposable Linux amd64 builder, materialize the exact cached parent as data in an isolated writable root using reviewed OCI tooling. Preserve paths, modes, numeric ownership, links, xattrs and whiteout semantics. Keep the executable and approved APK inputs outside the target root. Preserve no host credentials, ambient package caches or network access in the package transaction.
2. After tool qualification, validate the exact build's offline CLI and simulate a transaction against the existing package database and only the signed, hash-pinned local APKs. Require the solver to select exactly the approved revisions and no other package change. Configure the alternate root, empty remote repositories, no cache, no network, no scripts and no commit hooks. Preserve normal signature and dependency checks. The APK documentation explains that adding local APK files changes `world` by adding exact file identities. For an upgrade of only pre-existing libraries, preserve and independently validate the old `etc/apk/world` constraints. Only package database output tied to reconciled file bytes is eligible for the candidate. Check tool/version-specific switches and solver behavior before a commit. [Alpine APK global and commit options](https://github.com/alpinelinux/apk-tools/blob/master/doc/apk.8.scd#L214-L416), [APK add and world behavior](https://github.com/alpinelinux/apk-tools/blob/master/doc/apk-add.8.scd).

The runtime diff must consist of the approved package payloads and independently verified installed database records, plus the already-reviewed synthetic `gosu` stub and `User=postgres` derived settings. Match each owned path with the signed archive's bytes, ownership, mode and link metadata. Validate the package database's package identity, dependencies, provides, ownership records and checksums. Stop for dependency drift, required scripts, unexpected protected-file substitutions or unrelated state in the exported layer. Keep transaction logs, scratch databases and caches outside the OCI artifact.
4. Emit one static layer above the exact parent prefix with the reviewed path diff. Preserve inherited configuration and the narrower non-root user, and amend the existing static archive and source validators specifically to validate the changed payload rather than assuming their prior stub-only checks accept it. Resolved root checks must demonstrate the intended fixed binaries. The parent prefix still contains original bytes in lower layers. Independently run the exact-artifact SBOM, native, PostgreSQL core, advisory, KEV and rights checks before synthetic runtime use.
