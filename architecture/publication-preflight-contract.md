## Inputs and trust

`validate_publication_preflight(candidate_bundle, candidate_manifest, *, inventory_bundle, now)` is an offline function. A trusted caller supplies an independently sourced, current authored fixture inventory and an explicit aware time. The inventory's approved shared item records define the complete intended item set. The inventory must come from the trusted authoring process before the candidate is assembled. Never derive it from a candidate, client, model or upload. The function rejects identical bundle objects to catch accidental aliasing. Distinct Python objects cannot prove independence. The caller is responsible for obtaining the independent source and taking stable snapshots during validation.

Both bundles use the existing DEV-007 fixture-only contract. This slice accepts shared authored records only and rejects official specification claims. Both are independently validated at the supplied time. Every rights expiry must include a timezone offset or `Z` so its interpretation is independent of the ambient Django timezone. The original timestamp string remains part of the canonical record. Every candidate record must match its version and exact canonical bytes in the trusted inventory, including any unselected context record. Missing intended items fail even if omitted from both the candidate bundle and its manifest. Every selected item must have a rubric, profile, collection, edition, source materials, objectives and rights whose exact pinned records carry approved fixture metadata. Authoring context may retain unselected draft and withdrawn records that pass the base contract. A superseded edition may supply history for base validation and contributes no active pin solely because it is named by `supersedes`. The base validator still checks rights for every bundled material, including historical superseded context, so expired historical rights can hold the preflight. Historical or unapproved context is excluded from the result.

A candidate manifest has exactly `schema_version` with the string `1.0` and `records` with a nonempty list. Each pin has exactly `kind`, `id`, `version` and `sha256`. Kinds and identifiers follow DEV-007. Hashes are 64 lowercase hexadecimal characters of SHA-256 over the existing canonical UTF-8 record. Positive exact integer versions are capped at 2³¹−1. Both intended and actual active dependency closures must match the manifest exactly. Every collection member and its rights record is included. Unknown, empty, duplicate, extra, missing and changed pins fail. Choice items must have at least two options. The function performs no language-specific correctness, exposure, leakage or scoring checks. [Fixture and canonical contracts](../backend/modules/curriculum/contracts.py)

Before schema validation or hashing, each input payload is limited to exact JSON primitives, lists of up to 500 entries, objects of up to 32 fields with keys of up to 96 characters, individual strings up to 20,000 characters, two million aggregate characters, 50,000 values and a nesting depth of eight from the root. Bundles and manifests have at most 500 records or pins. There is no disk loading, file discovery, clock lookup or mutation. Nested validation failures are redacted to fixed `PreflightError` codes for time, manifest, inventory, candidate or coverage mismatch. Errors include no raw values, source text or answer keys.

## Result and remaining review

A successful call returns a frozen `PublicationPreflightReport` with status `structure_valid_assessment_held`. Each intended item has a frozen, exact item ID/version and fixed hold reasons. Deterministic modes require the actual grader and educator review. Human-review mode retains human handling and educator review. The report includes no prompts, sources, answers, ready decision, role or release capability. Reviewer metadata and authored rights fields provide structural test evidence within the selected contract. Legal, educational and access decisions require their separate authorities.

This function cannot publish, grant access, index data, grade or authorize assessment readiness. There are no grader callbacks or alternative grading semantics. Deferred acceptance includes semantic regressions with the exact grader and version, educator review, independent/assisted/exposed treatment, frozen holdouts, actual private ingestion, durable release/session pinning and real publication. The recorded AUTH-014 supplier wait, DEV-010 dependency and all phase/runtime checks continue to apply.
