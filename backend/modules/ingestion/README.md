# DEV-010 upload broker — in progress

This is the private lifecycle core, not a cleared parser/scanner or public upload feature. Default runtime assets are empty. Only explicitly registered authored-fixture hashes can use the test adapters; real SDK/native/model/definition/isolation review and actual execution are still required before DEV-010 completion or F3 exit. No HTTP write endpoint or UI is introduced.

The broker derives live actor/learner/course/edition/tutoring scope, reserves a byte quota covering source and derived manifest storage, streams into random private object IDs, checks declared/absolute bytes and type signature, and leaves content quarantined. Initial engineering fixture bounds are 8 MiB, 30 reported pages, 1 MiB output and 200,000 text characters; these are not commercial quotas or measured OCR fidelity. Input processing checks elapsed time/chunk count; a future transport must additionally enforce a hard ingress deadline. Signature screening does not prove a valid or safe PDF/image.

Local object storage uses a 0700 private root and 0600 exclusive no-follow files, never a user filename. Production/object-cloud adapters are not cleared. Quota remains held while a receiver owns an open descriptor and until deletion succeeds. Withdrawal denies access first, fences late work and permits idempotent purge retry; a failed purge cannot earn free space. A crashed writer requires verified ownership/closure recovery, not an assumed refund. Process retries are capped at three.

Default/unreviewed or failed scanners cannot reach parsing. Fixture results still need exact source/object/dispatch/generation/parser/type, bounded page/anchor/text schema and current live scope. Parser output is always needs_review, not approval. An explicit scoped ReviewGrant plus current membership is required to inspect/approve extraction and record a rights evidence reference/expiry; staff status or an uploader claim alone grants nothing. The service has no public API to create review grants. Manual review records are internal operational evidence, not legal certification. No shared/public/training promotion exists.

Every ready-source resolution rechecks requester access, edition/generation, state and rights expiry and verifies the stored manifest hash/schema. Consent generation changes invalidate old uploads even after a later regrant. New editions/uploads get new object IDs; originals are not silently overwritten. Deletion purges originals and manifests here; indexes/caches/processor stores do not exist yet and must participate when introduced.

The current process callback is a synthetic broker seam, not an OS isolation boundary. Dedicated signed-manifest helpers are tested, but a real offline Docling worker, malware scanner/signature freshness, native dependency/model rights, CPU/RAM/process/output limits and no-egress/filesystem proof remain unimplemented. Never enable arbitrary qualified-runtime records or run unreviewed files merely to obtain a passing lifecycle test.

Minimal Docling PDF candidate: docling-slim[format-pdf-docling] 2.150.1, 43 metadata-resolved packages, no parser installed. The observed Python advisory audit found no known vulnerabilities; that excludes native-library/model/engine closure and is not a security pass. ClamAV 1.5.4 is a release candidate only.
