# DEV-009 synthetic job foundation

Jobs are a durable PostgreSQL work queue, not a newly deployed worker service. Internal commands enqueue, claim, complete, recover an expired lease, cancel and reconcile usage. No HTTP write API or provider SDK is introduced. Only mock-a and mock-b are eligible; no external data or money is sent. Real model selection, quality/privacy qualification and tariffs remain gated.

A command key is unique per actor and start command; its hash pins the resource and bounded request. An identical replay returns the existing job. A changed body conflicts. Budget rows are scoped to learner/course/purpose, and integer synthetic units satisfy spent + reserved <= limit. Budget then job then learner locks serialize reservation, claims and completion. A worker gets a monotonically increasing fence and a 30-second lease; the job has a ten-minute deadline and at most three attempts. Known not-billed failures retry with bounded exponential delay plus zero/one-second deterministic jitter. Unknown billing keeps its reservation and does not retry automatically.

Provider dispatch and cancellation happen outside database transactions. A crash after dispatch may have billed: expired running work becomes unknown, not a fresh free attempt. A receipt records provider request ID, input/cache/output/audio units and mock tariff version. Identical receipt replay is idempotent; conflicting receipts fail. Cached tokens are observed receipt units, never an assumed discount. These mock budget units are not dollars or vendor billing measurements.

A cancelled or expired/stale worker can settle legitimate usage but cannot mark work successful or write a learning result. No mastery, grading, roles or payment effects exist here. Exact learner/course/purpose/edition and authorization generation are pinned. Current authorization is checked at dispatch and completion. Canonical consent withdrawal increments the learner's authorization generation while holding its row lock, so a later regrant cannot revive old work. Grant new consent as a new record; never clear withdrawn_at. Future membership, relationship, rights and deletion workflows must also invalidate learner work and use live authorization. The current internal consent service is not a public or legally approved consent workflow.

Cancellation is durable first, upstream best effort second. A cancellation acknowledgement does not imply no charge; outstanding reservations remain until an actual mock receipt or explicitly reviewed fixture not-billed evidence settles them. Unknown vendor billing, worker leases and queue state survive process interruption because they are database records. No automatic operator reconciliation, daemon scheduler, heartbeat renewal, external outbox send or paid fallback is claimed.

The budget currently has a fixed total, not a daily plan or production price model. Future UI/actions must use server-side CSRF/idempotency/version contracts; future real providers need their own exact approval, SDK/model/content/processor rights, request limits, cancellation and receipt evals. Prompts/context caches, the Jev benchmark, real voice, cost/retention benchmarks, timed backup restore and RPO/RTO remain unimplemented. No learning efficacy follows from these synthetic tests.
