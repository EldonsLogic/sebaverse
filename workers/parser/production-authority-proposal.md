# DEV-010 production parser authority proposal

20 November 2026 · R039/R040/R041/R046 · RISK-F3-004. Referenced implementation at `8a413d8`. Proposed design for independent architecture and security review. The risk is that a compromised parser could forge clean-scan authority, read another learner’s source or return a result after access is revoked. This increment is one design record for the disabled runtime. It makes no activation, qualification or gate decision. [Risk register](../../registers/decisions-risks-unknowns.md#L120), [ADR-014](../../architecture/adr/ADR-014-minimal-digital-pdf-poc.md).

## Authority and existing evidence

The broker currently checks the scanner adapter’s three-field result (`asset_id`, `sha256`, `status`), a server-owned asset allowlist and the live dispatch. The digital-PDF core separately verifies signed job and scan envelopes using two HMAC keys. Those envelopes have only been composed across a process boundary with public authored-fixture keys. HMAC gives its key holder signing ability, so moving those keys into a production parser would let it mint both envelopes. A clean scanner verdict establishes the approved scan result for particular bytes. It leaves extraction fidelity, content rights and publication to their own checks. [Broker process](../../backend/modules/ingestion/service.py#L131), [PDF core](digital_pdf.py#L175), [authored evidence](../../development/evidence/dev-010-authored-input.md).

## Proposed single-dispatch handoff

1. The broker checks live permissions and reviewed runtime assets and captures the current object and active dispatch under the existing lifecycle locks. It retains its own exact eight-field job snapshot: object ID, source SHA-256, generation, dispatch ID, parser identity, media type, byte count and opaque server-derived scope digest. The live scope recheck uses the persisted authorization generation, relationship, consent, grant, purpose and curriculum edition. The broker reads just the quarantined source selected by that row, bounds length by the existing 8 MiB ceiling and stored count, checks PDF signature/type and matches the stored hash. It stages the source in an immutable local object before scanning.
2. The approved scanner boundary scans bytes from that same sealed object and independently measures the source hash and count. It returns a bounded clean attestation bound to the eight job fields, approved scanner identity and short expiry, using the existing scan envelope format. A scanner-side trusted component can bind the verdict to the dispatch; its authority must come from the approved scanner invocation and measured input. The broker validates both signed envelopes against its own captured values and a trusted clock, including exact fields and the existing expiry window of at most 120 seconds. Dirty, failed, missing, stale, mismatched or unverifiable scan evidence leaves the source held. The current unsigned adapter dictionary alone is insufficient for this proposal.
3. After scan verification, the broker rechecks the live scope and current generation and dispatch under the existing locks. Only the trusted launcher may pass an already-open read-only descriptor for that one immutable object to one fresh parser process. Stdin carries bounded job metadata for extraction and result binding. The child gets no signed envelopes, signing or verification keys, storage path, URL, directory handle or storage credential. It gets no learner database or provider access. The launcher selects the reviewed worker, input descriptor slot and limits in server-owned composition. The child has no source lookup mechanism. If an immutable one-object handoff is unavailable, the broker stays closed.
4. The child reads the exact bounded source length and checks type and hash before opening the engine. Preserve the existing bounded extraction and `needs_review` result schema. The broker accepts output only on the pipe for this invocation. It independently decodes and validates against its captured provenance, then rechecks live permissions, review requirements, expiry and current dispatch before accepting a manifest for review under the existing quota and lifecycle controls. Child output cannot attest to the scan or approve a source. Malformed output, child failure, expiry, cancellation or revocation discards output and closes the handoff. Cleanup must account for the entire worker process tree. Every retry starts a new dispatch with a newly verified scan and a new descriptor. Cancellation can stop further reads and reject stale output after access changes. Bytes already delivered to a child cannot be recalled. [Existing dispatch fences](../../backend/modules/ingestion/service.py#L121), [result decoder](result_transport.py#L57).

## Qualification still required

- **Credential trust.** If HMAC is retained, keep separate job and scan keys scoped to one dispatch and provision them only to the authorized endpoints. The broker verifies with the scanner key and is therefore trusted to keep it and to honor the independent verdict. This retains the existing cryptographic primitives and adds no dependency. It provides no protection from a dishonest broker and no third-party proof of who signed. Qualify how distinct scanner identity, key delivery, expiry, rotation and revocation work and how the scanner-side signer authenticates its scan invocation and binds the verdict to the measured bytes. Keep keys out of both native engine processes, output and diagnostics. There is no reviewed production provisioning mechanism today.
- **Immutable input and isolation.** One Linux candidate is an anonymous sealed file with verified write, grow, shrink and further-sealing restrictions, handed off through a read-only descriptor. The scan and parser must receive the same sealed bytes and the launcher must verify descriptor identity, access mode, seals and layout before handoff. Qualify the exact kernel/runtime, descriptor ownership and cleanup, immutable executable/imports, process identity and isolation from the parent, filesystem and cross-job access, all egress, CPU/RAM/process limits, and termination of descendants. Account for staging copies and any swap or crash artifacts. A read-only open on a mutable inode, script hashing and the current watchdog alone cannot establish these properties. [Linux man-pages `memfd_create`](https://man7.org/linux/man-pages/man2/memfd_create.2.html), [file seals](https://man7.org/linux/man-pages/man2/F_ADD_SEALS.2const.html), [existing guard contract](process-guard-contract.md).
- **Compatibility and approval.** Keep `digital_pdf.run_job`, the authored fixture and its existing tests compatible. If approved, share the bounded extraction logic with a parser entry point reachable only through the qualified launcher. The signed job and scan stay with the trusted broker. This proposal changes where ADR-014’s signed job and clean-scan checks run. Record the reviewed decision before implementing the production composition. AUTH-014 remains in supplier wait. [Digital-PDF contract](digital-pdf-contract.md), [AUTH-014](../../development/APPROVALS.md#auth-014--recovery-choice--wait-for-supplier-20-november-2026).

## Negative acceptance for a later implementation

1. Assert no parser launch or source handoff on missing, dirty, unknown-signer, invalid-signature, expired or replayed scan evidence. Exercise every mismatched binding field, concurrent dispatches, scope changes and source length/type/hash drift. An actor controlling child input or output must be unable to supply scanner authority.
2. Assert no launch on wrong or mutable descriptors, missing seals, substituted sources, writable aliases or inherited extra handles. In the qualified OS boundary, verify that the child can read just its own source, cannot modify it or obtain another source or parent credentials, cannot use storage or database access or egress, and cannot leave surviving descendants or retained handoff files.
3. Exercise cancellation, consent withdrawal, deletion, retry and expiry during scan, at handoff and before manifest acceptance. A late or incorrect result, including job B’s valid output sent as job A’s, must fail closed without a new manifest or quota leak. A clean case should reach only `needs_review` with bounded output. Run authored compatibility tests and record actual scanner, launcher, and independent review evidence when authorized. Native Arabic and bilingual fidelity and the remaining F3 checks still require their own evidence.

Root checked the two primary manual pages on 20 November: memfd descriptors initially permit reads and writes, and sealing requires explicit supported kernel operations. The proposal therefore treats verified seals and a separately verified read-only handoff as qualification work, not a property already established by descriptor creation. No primitive was executed or runtime qualified. Independent architecture/security review is pending because the assigned agents stopped at the usage limit.
