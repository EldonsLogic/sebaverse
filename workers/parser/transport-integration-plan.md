# DEV-010 worker result transport

20 November 2026 · AUTH-013 · R040/R041/R046. Add a strict decoder for bounded worker stdout that reuses the existing broker result validator. The guard returns opaque bytes, and the validator currently accepts Python dictionaries. Conversion between them is a trust boundary. A duplicate JSON member can disappear before dictionary validation, and output from a completed child can still claim the wrong job or authority. [Process guard contract](process-guard-contract.md), [existing result validator](../../backend/modules/ingestion/contracts.py), [broker lifecycle](../../backend/modules/ingestion/service.py).

Threat and budget. Ambiguous or fabricated worker output could be accepted under the wrong dispatch in a future transport. The immediate scope is authored fixtures with no learner data. One pure implementation module and one independently owned test file, with up to two corrections.

## Interface and acceptance

- `workers/parser/result_transport.py` exports `ResultTransportError(ValueError)` and `decode_result(output: bytes, expected: dict) -> dict`. Reject non-byte input and raw output above `MAX_OUTPUT` before decoding. Decode strict UTF-8 and one JSON value, rejecting duplicate object members at any level and non-finite or unsupported numeric values. Malformed, excessive-depth and unencodable text failures return the same bounded reason, with no raw bytes or exception details.
- Copy the six bounded provenance primitives from the trusted caller's expected binding before parsing. Validate the decoded object using `validate_result`. The current schema determines page, anchor and text limits and `needs_review` status. The output can neither update the expected binding nor carry scope or approval fields. The caller still owns live permissions and rechecks object generation and dispatch before any publication.
- `backend/tests/ingestion/test_result_transport.py` owns positive multilingual and negative wire cases. Cover malformed/alternate encodings, oversized bytes, deep JSON, duplicate fields at root and block level, bad provenance, anchors or limits, and forbidden approval fields. Include a bounded actual guard stdout round-trip with the existing authored echo process. Run the focused file, then `make test-ingestion` and have an independent reviewer check the exact code and fixture results. These checks require neither PostgreSQL nor native extraction.

The parser and asset registry remain disabled by default. Live broker dispatch and stored-manifest reads continue through their existing contracts. The generic process guard caps input at 1 MiB while ingress allows 8 MiB, so file input framing and scoped credential transfer require a separately reviewed boundary. Native PDFium, scanner, worker image and OS isolation remain held, as do real extraction fidelity and DEV-010/F3 exit.
