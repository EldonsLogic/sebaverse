# DEV-010 alternate PDF backend review

18 November 2026. AUTH-008 screened one alternate, Docling Slim 2.150.1 with its PyPDFium2 backend and the PyPI `pypdfium2` 5.15.2 Linux x86-64 wheel. It removes the original Docling Parse wheel from the dependency graph and provides an offline text-layer path in the pinned SDK source. Native review remains open. Installation and runtime qualification remain on hold.

Threat and budget. PDFs reach native parsers and can exhaust or compromise the disposable runner. The review covers the dependencies and evidence for one backend within one engineering day. A worker run still requires the project’s dependency, scanner, isolation and execution gates.

## Offline SDK path after review

The exact Docling wheel's `docling/backend/pypdfium2_backend.py:791` emits segmented PDF text lines with geometry. Its word and character cell lists are empty. `docling/pipeline/native_pdf_pipeline.py:253` reads those page results and supplies provenance boxes. The Docling CLI maps `PdfBackend.PYPDFIUM2` to `PyPdfiumDocumentBackend`, and the wheel's CLI entry point requires the full local model stack. Use the model-free SDK path with `DocumentConverter(allowed_formats=[InputFormat.PDF])` and the PDF format configured explicitly as `PdfFormatOption(backend=PyPdfiumDocumentBackend, pipeline_cls=NativePdfPipeline, backend_options=PdfBackendOptions(), pipeline_options=...)`. Set `NativePdfPipelineOptions` to `text_cell_unit=TextCellUnit.LINE`, `generate_page_images=False`, `generate_picture_images=False`, `enable_remote_services=False` and `allow_external_plugins=False`. Supply a broker-provided local path, pass manifest bounds through `max_file_size`, `max_num_pages` and `document_timeout`, and keep egress denied at the operating-system boundary. This path has no model download step. Static source shows the interfaces match. The combination and import closure have yet to run. [Exact Docling Slim release wheel](https://pypi.org/project/docling-slim/2.150.1/#files)

The first run should use the existing broker manifest and exact scanner attestation in an offline, non-root worker with a read-only job input, capped output and hard process limits. Check text, page numbers and anchors on authored digital PDFs. Include Arabic and bilingual text, rotated pages and critical notation, with malformed, image-only, partial, over-limit and cancelled cases held before publication. Line-level success would establish the digital-PDF path. R039 still requires representative reading order, layout, OCR, table, diagram and notation fidelity with separately reviewed assets and actual tests.
