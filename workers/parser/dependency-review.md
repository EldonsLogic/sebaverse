# DEV-010 Docling candidate review

18 November 2026. The first real extraction can use Docling's model-free PDF pipeline once the exact wheel and runtime review closes. The candidate is still held before installation. This review covers DEV-010 and R037–R042/R046, with the first run bounded to authored digital PDFs.

Threat and budget. Native code processing a PDF could exhaust resources or escape its worker. At this stage the exposure is the disposable synthetic runner and anything mistakenly mounted or injected into it. Budget one review pass and one bounded smoke run after the dependency and isolation checks pass.

## First extraction run after review

1. Build a disposable worker offline from the reviewed wheel set and pinned runtime image. Use a non-root process, no network, no inherited secrets, no learner database or storage credentials, a read-only root and job input, and bounded disposable scratch. Enforce CPU, memory, process, byte, page, output and wall-time limits outside the library. Verify isolation, forced termination and cleanup on cancellation or timeout.
2. Require the scanner's clean verdict for the exact input hash and a valid scope-bound broker manifest. Allow only PDF and a broker-supplied local input. Use `NativePdfFormatOption` with `NativePdfPipelineOptions`, one parser thread, and page rendering and picture decoding disabled. Set `max_file_size`, `max_num_pages` and a document timeout from the worker limits. The pinned release uses threaded `docling-parse` to obtain native text cells and page boxes. `StandardPdfPipeline` still initializes layout with OCR and table structure disabled. [Native option wiring](https://github.com/docling-project/docling/blob/v2.150.1/docling/document_converter.py#L364-L392), [native pipeline](https://github.com/docling-project/docling/blob/v2.150.1/docling/pipeline/native_pdf_pipeline.py#L76-L85), [standard layout initialization](https://github.com/docling-project/docling/blob/v2.150.1/docling/pipeline/standard_pdf_pipeline.py#L619-L651)
3. Check expected text, page numbers and bounding boxes on an authored text-layer PDF. Verify that malformed, over-limit, image-only and partial results, and stale or withdrawn jobs, cannot publish usable extraction. Include scanner outage and mismatched hash or generation cases. Explicitly inspect the conversion status because `raises_on_error=True` accepts `PARTIAL_SUCCESS`. [Conversion status handling](https://github.com/docling-project/docling/blob/v2.150.1/docling/document_converter.py#L791-L807)
