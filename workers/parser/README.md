# Parser boundary — DEV-010 in progress

AUTH-013 / ADR-014 selects the same-engine direct PyPDFium2 route for the first authored text-only PDF PoC. The [owned worker core](digital_pdf.py) and [independent fake-engine tests](../../backend/tests/ingestion/test_digital_pdf.py) are implemented. Native PyPDFium2 is not installed or executed; no factory is configured by default, and no public upload/broker path or approved runtime registry is enabled. Docling remains the advanced extraction direction pending its separate qualification.

The core verifies bounded primitive job/scan envelopes, separate effective HMAC keys, expiry, exact object/dispatch/generation/source/scope bindings and source byte count/signature/hash before opening any document. It then enforces reported page/character limits, strict bounded text chunks, stable page/offset anchors, cumulative/serialized output bounds and needs_review output. Failed signatures, non-clean or mismatched scan, missing runtime and malformed results fail closed. Exact API and roles: [worker contract](digital-pdf-contract.md).

The document factory, trusted expected values, clock and keys are internal composition/test inputs, never client/model configuration. Future key management must use dedicated job-scoped credentials, with no learner DB/cloud/provider credentials inside the parser. The live broker remains responsible for authorization/consent/edition/rights, one-time dispatch/cancellation, stale-result fencing, private publication and withdrawal. HMACs do not create those grants or qualify a scanner.

Every acquired text/page/document handle is closed in reverse order, including failure. Errors contain bounded reason codes rather than document contents or arbitrary native messages. The ten-second monotonic checks cover calls that return; they do not kill native hangs or bound native allocations. A reviewed parent watchdog and OS CPU/RAM/process/output/egress/filesystem controls remain mandatory. No OS isolation, real cancellation transport or actual extraction fidelity is established by unit tests.

The cached SDK warns that native indices and extracted lengths can differ and its range API is UCS-2 limited. This PoC holds mismatches, blank/image-only pages and undecodable content rather than normalizing or silently dropping notation. Such holds can reject legitimate PDFs. Arabic/bilingual order, actual Unicode behavior, tables, diagrams, math and OCR require real authorized fixtures after qualification. No native capability or learning effectiveness is inferred from fake Arabic/German strings.

Local checks: make test-ingestion covers 96 database-free cases, including 64 direct-adapter cases; actual PDFium/scanner/worker-image/OS tests remain unrun. [Independent review](../../development/evidence/dev-010-direct-adapter-review.md), [direct candidate and exact artifact](direct-candidate.json), [native evidence](native-closure-review.md), [shared dependency inventory](shared-wheel-inventory.md). Completing this core does not close DEV-010 or pass F3.
