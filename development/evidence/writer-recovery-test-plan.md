# DEV-010 local writer recovery test plan

22 November 2026 · R040/R046 · Source reviewed at `dceee32`. A mistaken recovery can leave a private file after withdrawal and return quota while the writer can still create bytes. Exposure is limited to authored fixtures. This plan covers one local recovery path and its regression tests under the existing cleanup scope. [AUTH-015](../APPROVALS.md#auth-015--founder-narrow-consent-cleanup-and-full-file-purge-21-november-2026) · [Ingestion specification](../../docs/04-curriculum-and-rag.md#ingestion-and-version-lifecycle)

## Observed gap

`accept_bytes` commits `writer_active=True` before `PrivateObjects.put` opens the original. The cleanup consumer and manual withdrawal fence access but retain quota while that bit is set. A paused writer can resume and open the file, and abrupt process exit can leave the bit set even after the OS closes the descriptors. Existing fake-store tests clear the flag directly. The staged PostgreSQL case exercises cooperative closure, and its result remains pending. Manifest writes already use the upload lifecycle transaction and dispatch checks. ## Acceptance cases

Use valid authored bytes, a temporary private root and synchronization points with deadlines. A child process must open an independent lock descriptor. Only terminate the child the test created. Assert file names via no-follow checks and assert the upload row and quota counters together.

| Case | Required observation |
| --- | --- |
| Receiver pauses after committing the active marker, before opening the blob | Recovery fences access and returns a recoverable blocked result while the writer's guard is held. Even with both names absent, no purge receipt or credit is issued. Resume the receiver and check that its stale generation cannot advance to quarantine or publish. |
| Receiver pauses before acquiring the guard | An independently authorized withdrawal completes and confirms absence. When the stale receiver resumes, its locked state check rejects the request before opening the file or changing any lifecycle fields. Original and manifest remain absent and quota stays settled exactly once. |
| Child exits abruptly with the blob descriptor open | While the child is alive, a distinct process cannot acquire the recovery guard and the charge remains. After the test terminates and waits for its own child, recovery can acquire the same guard while the partial file still exists. The approved cleanup path removes original and manifest, clears the active marker and records terminal confirmation with one quota credit. Also test exit before blob creation and after blob closure but before receiver state finalization. |
| Local proof or identity is uncertain | Reject a legacy active marker, missing/invalid proof, wrong UUID, stale generation, another storage root and unavailable or unsupported locking. Inject a changed lock inode and ensure a fresh inode cannot stand in for the original. No proof failure may purge, clear the active marker or credit quota. The lock inode is retained after successful recovery and retries. If lock stripes are shared, a collision may defer cleanup and may never dispose of the other UUID or its quota. |
| Manifest dispatch overlaps recovery | Exercise a dispatch paused before manifest creation. The committed withdrawal fence prevents the stale dispatch from opening a manifest upon resumption. Exercise a manifest writer already in the final transaction and require cleanup's state fence and absence receipt to order after that transaction. Any lock acquisition while a transaction is held must be bounded and free of lock-order inversion. |
| Purge fails or accounting loses authority | Inject failure after the first unlink, on directory synchronization, and after confirmation but before accounting. Both charges stay held until both names are confirmed absent. A consumer that loses its lease cannot settle. Replay reconciles once after revalidating upload UUID/generation, scope and current lease. Neighbouring, later-generation and regranted uploads keep their files and charges. |

Test the service entry points in addition to the OS primitive. In-memory lifecycle tests can stage failure and replay. Real transaction ordering, rollback and independent connections belong in the PostgreSQL suite when its execution is authorized. Preserve existing authorization and cleanup regressions. Neither time elapsed nor a PID check proves closure. Keep any unsupported or multi-host composition blocked until qualified. Local confirmation covers the original and manifest names in the same trusted directory under the supported guard protocol.

## Actual evidence

A standalone Python 3.9.6 probe on Darwin used only standard libraries and a temporary directory. A child obtained an exclusive `flock`, opened and flushed an authored partial file, then signalled readiness through a pipe. The independent parent descriptor saw contention. After abrupt child exit and reap, the parent acquired the same inode while the partial file still existed. Exit code 0. This establishes the local host primitive.

On Darwin with the repository Python 3.12 environment, `make test-ingestion` passed 298 cases, including 27 new writer-recovery cases. The tests combine real local files and subprocesses with in-memory lifecycle and consent-intent rows. They exercise the receiver, consent consumer and manual withdrawal entry points. Two cases confirm the raw descriptor is closed when stream initialization raises, while the live guard still excludes a recovery attempt. Initial ingestion runs exposed fixture interface mismatches for `save(update_fields=...)` and `fdopen(closefd=...)`. The test adapters were corrected before the passing run.
