## Work packages and milestone outputs

M0 Foundation (this deliverable): context audit, 96-entry requirements baseline, preserved research, PRD/design/architecture, economics and execution system. Final historic completeness remains open. No fixed completion date for founder reviews.

M1 Product/brand/design: select one slice and customer promise; review hypotheses against existing prospects; identify content/educator; screen three names and choose; test low-fidelity student/parent/upload/voice journeys; record decisions. Estimate 1–2 founder weeks plus external name/rights/legal lead time as a new planning assumption, not research fact. Stop if no lawful affordable content/data route.

M2 Architecture gate: compare framework options and record ADRs, authorize minimal dependencies, threat model and contracts, define eval sets/budgets and operations ownership. Estimate 3–5 focused engineering days plus reviewer lead time, provisional. Do not install whole upstream apps merely to decide.

M3 Bounded technical PoC: A11 estimates 10–15 engineer-days plus 2–3 educator-days; actual solo calendar time includes availability and external review. One unit, 10–20 concepts, 120 reviewed grading items, 20–30 source pages, 100 retrieval questions, 30 injection documents, >=100 authorization negatives, synthetic identities and initially adult voluntary audio only. No live payments, WhatsApp sends or real-minor data. Days 1–2 contracts/scope; 3–4 parser/retrieval; 5–6 bounded tutor/receipts; 7–8 evidence/rules; 9–10 guardian view/grant fixtures; 11–12 replay/evals/recovery; 13–15 optional voice/provider/Jev/reuse comparisons only within cap. Because the required comparisons add work, prioritize baseline runnable loop and report any benchmark not executed; do not imply all providers fit the original time estimate. A failed privacy gate blocks pilot. Stop DeepTutor extraction if it drags in full runtime or >3 repair days.

M4 Supervised pilot: research range 10–16 engineer-weeks after PoC, plus educator/legal/content/support effort, not a delivery promise. WBS: accounts/consent/grants → approved curriculum/items → grounded text/independent practice → explainable state/review → private uploads/manual review → parent dashboard/preferences → metering/support/deletion/recovery → capped voice if passed. Manual entitlements acceptable. Recruit 10–20 family/friends only after G5. Track support time and delayed results; no broad efficacy claim.

M5 Commercial hardening: current payments/refunds/tax, accessibility/RTL, load/security review, actual plan quotas, opt-in messaging and incident/support capacity. Calendar estimate deferred until pilot data. M6 expansion: exam breadth, richer interactive lessons, teacher/schools, curricula and local inference in evidence-driven increments. Optional model training/RL/neural KT require distinct ADRs, data rights and demonstrated advantage.

## Change control and dependency discipline

New requirement gets source, stable ID, priority, dependencies, phase and acceptance. A deferral records reason, trigger and owner; deletion/rejection needs explicit founder decision and retained historical row. Amend affected specs/ADRs/evals/economics together. Do not weaken failed acceptance thresholds without documenting tradeoff and founder/reviewer approval. Approved gate record includes date, reviewed artifact commit, approver, conditions and unresolved risks; gate default stays pending. Brand-folder rename is a later project-management action after selection, preserving Git history and links.
